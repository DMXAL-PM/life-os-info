Application privacy

Privacy policy

Life OS Personal is a personal planning application operated by its owner on a Mac. This policy describes the application’s Google Calendar connection and optional AI features. Updated October 19, 2026.

Information accessed

Google sign-in supplies an account identifier and email address. Calendar access supplies calendar names, identifiers, timezones and access roles, plus selected calendars’ event identifiers, titles, timing, recurrence and busy/free status. For a proposed edit, Life OS also checks event version and whether the event has guests or other unsupported characteristics. It does not import attendee email addresses, event descriptions, locations or conferencing details through this integration.

How information is used

Life OS uses this information to identify the connected account, show the selected calendar agenda, calculate planning availability, review conflicts and execute explicitly approved event changes. Google’s permission applies at account scope; Life OS limits its operation to the calendars selected in the application. Google’s edit permission includes capabilities that Life OS does not expose, such as event deletion.

Storage and retention

Saved calendar views, planning snapshots, proposals and action history are stored in the local database. Google access and refresh tokens are encrypted before database storage; the encryption key and client configuration are kept in an owner-only local file. Database records and their backups are not all separately encrypted by the application. The owner controls the Mac, its disk protection and backup locations.

Refreshing the agenda replaces its current bounded event snapshot. Historical briefs, reviews and action records remain until the owner removes the relevant local records or installation. Backups and exports can retain earlier copies and must be managed separately.

Sharing and optional AI

Life OS sends authentication and calendar requests to Google to provide the selected connection. Calendar synchronization alone does not send events to OpenAI. If the owner separately reviews and approves an AI planning request, the displayed input can include event titles, identifiers, times, busy/free status, availability and other selected planning records. That approved input is sent to OpenAI through the owner’s subscription and is subject to the account’s terms and data controls. Review those controls before approving sensitive information.

Separately authorized agents receive only information allowed by their Life OS grants. Calendar-request status tools do not expose the private agenda; explicitly sharing a scheduling draft makes that draft available to agents with access to its project. Tokens and client credentials are not part of these AI inputs or agent results.

Life OS does not sell Google user data or use it for advertising. Google API data is intended only for the user-facing planning and calendar features described here, subject to the Google API Services User Data Policy and Limited Use requirements. It must not be used to train generalized AI models.

Disconnecting and removing information

Settings → Disconnect local sync deletes Life OS’s saved Google tokens and stops future refresh. It retains the last saved agenda and historical records. To revoke Google’s authorization separately, use Google account connections. Disconnecting does not delete events from Google Calendar. The owner can remove local records, backups and exports independently; keep a suitable recovery copy before removing data.

This public website

These static information pages contain no application login, calendar data, analytics scripts or advertising. If published on GitHub Pages, GitHub handles website requests under the GitHub privacy statement.
